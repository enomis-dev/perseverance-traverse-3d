# Perseverance Traverse 3D

An interactive 3D viewer of Jezero Crater, Mars, built with [CesiumJS](https://cesium.com/platform/cesiumjs/), showing real terrain, real imagery, and the actual traverse path of NASA's Perseverance rover since it landed in February 2021.

**Live**: https://enomis-dev.github.io/perseverance-traverse-3d/

- Mars ellipsoid (not Earth's WGS84): equatorial radius 3,396,190 m, polar radius 3,376,200 m
- Terrain relief for the whole crater
- Real NASA imagery (Viking color mosaic, MOLA colorized elevation)
- The rover's actual tracked path, sol by sol
- Landing site and notable sample-collection stops, clickable for details

## Running it locally

```bash
npm install
cp .env.example .env   # fill your own Cesium ion access token
npm run dev
```

Then open **http://localhost:5173** (Vite's default dev port).

You'll need a free [Cesium ion](https://ion.cesium.com/) account for the access token. The app doesn't currently stream anything from ion (see [Terrain](#terrain) below), but CesiumJS expects a token to be set regardless.

### Other scripts

```bash
npm run build      # production build -> dist/
npm run preview    # serve the production build locally
```

## Application structure

JavaScript on Vite + CesiumJS.

| File | Responsibility |
|---|---|
| `src/main.js` | Entry point: builds the `Viewer` on the Mars ellipsoid, wires up terrain/imagery/traverse, camera framing, UI (basemap toggle, MOLA legend, lat/lon readout) |
| `src/marsImagery.js` | Builds the two Mars Trek WMTS imagery providers |
| `src/traverse.js` | Fetches rover waypoints, renders the sol-colored traverse polyline and notable-site markers |
| `src/scrubber.js` | The sol slider and the rover-position marker that tracks it |
| `src/solDate.js` | Sol number → approximate Earth date |
| `src/data/notableSites.js` | Hand-curated landing/sample/milestone site data |
| `public/data/m20_waypoints.json` | Local snapshot of the rover traverse feed (see below for why it's a snapshot, not a live fetch) |
| `public/terrain/` | Pre-generated static terrain tiles (quantized-mesh), served as plain files, no backend at runtime |

The terrain tiles in `public/terrain/` were generated by a **separate, one-time pipeline** that isn't part of the shipped app and doesn't run in the browser: GDAL (reprojection, merging) + a patched copy of [`ctod`](https://github.com/sogelink-research/ctod) (Python, tiling), run once locally to produce static files. 

## Data sources

### Imagery (NASA Mars Trek, WMTS)

Both layers stream live from NASA/JPL/USGS's public Mars Trek tile service, credited to **NASA / JPL-Caltech / USGS**:

- **Color mosaic** (default basemap): Viking MDIM 2.1 global color mosaic, ~232 m/pixel
  `https://trek.nasa.gov/tiles/Mars/EQ/Mars_Viking_MDIM21_ClrMosaic_global_232m/...`
- **MOLA colorized elevation** (toggle-able): MGS MOLA global color shaded relief, ~463 m/pixel
  `https://trek.nasa.gov/tiles/Mars/EQ/Mars_MGS_MOLA_ClrShade_merge_global_463m/...`
  Global elevation range −8,200 m to +21,229 m (Hellas Basin to Olympus Mons); purple = low, white = high.

### Rover traverse (NASA JPL Mars 2020 / MMGIS)

Source: `https://mars.nasa.gov/mmgis-maps/M20/Layers/json/M20_waypoints.json`, NASA's own live, hourly-updated "Where is Perseverance" feed. Credited to **NASA / JPL-Caltech**.

This is bundled as a **local snapshot** (`public/data/m20_waypoints.json`, trimmed to the fields this app uses) rather than fetched live, because that endpoint doesn't send `Access-Control-Allow-Origin`, so browsers block the cross-origin fetch outright. The snapshot reflects 703 waypoints, sol 13 through sol 1980, as of September 2026.

Notable-site markers (landing site, sample-collection stops, mission milestones) in `src/data/notableSites.js` are a **best-effort** overlay: the waypoints feed itself doesn't reliably tag sample events, so public mission reporting (e.g. "Rochette core, ~sol 194") was matched to the nearest real tracked waypoint. The displayed sol is real; the narrative sol is approximate.

### Terrain

Two USGS-hosted elevation sources, merged:

- **HiRISE DTM** (fine detail, 1 m/pixel): *Mars 2020 Terrain Relative Navigation HiRISE DTM Mosaic*, covering the landing ellipse and delta (~77.22–77.58°E, 18.31–18.67°N). Produced by USGS Astrogeology + JPL for landing hazard-avoidance planning.
  `https://asc-pds-services.s3.us-west-2.amazonaws.com/mosaic/mars2020_trn/HiRISE/JEZ_hirise_soc_006_DTM_MOLAtopography_DeltaGeoid_1m_Eqc_latTs0_lon0_blend40.tif` (1.84 GB)
- **MOLA global DEM** (coarse base, ~463 m/pixel): fills in the rest of the crater, including the rim, where HiRISE doesn't reach.
  `https://asc-pds-services.s3.us-west-2.amazonaws.com/mosaic/Mars_MGS_MOLA_DEM_mosaic_global_463m.tif`

Both are credited to **NASA / JPL-Caltech / USGS**, HiRISE additionally to the **University of Arizona** (the instrument's operating institution).

**Why they're merged, not just one or the other**: HiRISE alone only covers the landing ellipse (~36×21 km), a small fraction of the ~45 km-diameter crater. MOLA alone covers everything but at 463 m/pixel, far too coarse to show real relief at rover scale. The two were composited into a single raster (HiRISE pixels win wherever available, MOLA fills the rest), reprojected to Mars's true ellipsoid, then tiled into the static quantized-mesh pyramid served from `public/terrain/` (zoom levels 0–13, ~3,200 tiles, ~25 MB).
